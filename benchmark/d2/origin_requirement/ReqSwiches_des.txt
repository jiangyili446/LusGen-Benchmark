Defines four nodes: Switch1, Switch2, Switch3, and ReqSwitches, aiming to implement a switch model with two buttons (Set and Reset).

Node Switch1 receives three Boolean inputs: Set, Reset, and Init, and returns a Boolean output X. Its logic is: if the Set button is pressed, the output X is true; if the Reset button is pressed, the output X is false; if neither button is pressed, the value of X depends on the Init signal and is determined based on the previous value of X.

Node Switch2 has a structure similar to Switch1, but with different priority logic: if the Reset button is pressed, the output X is false; if Set is pressed, the output X is true; when neither button is pressed, the value of X is still determined based on the Init signal and the previous value of X. This node implements a logic that prefers reset when Set and Reset are pressed simultaneously.

Node Switch3 is a more compact form that integrates the switch logic: output X is true when Set is true, and dependent on the previous X when Reset is false and under the Init signal condition. If Reset is true, then X is unconditionally false.

Next, the ReqSwitches node is defined, receiving the same Set, Reset, and Init inputs, and returning three Boolean outputs: R1, R1b, and R2. Internally, S1, S2, and S3 are defined as the outputs obtained from calling Switch1, Switch2, and Switch3.

The logic for R1 indicates that if Set and Reset are never true simultaneously, the outputs of Switch1 and Switch2 should be the same. However, this logic is not accurate, so a stronger assumption is made in R1b: using an auxiliary node Sofar to ensure that Set and Reset have never been true simultaneously before the current moment, allowing for the correct determination of whether S1 and S2 are equal.

Finally, R2 is used to check if the outputs of Switch1 and Switch3 are consistent under all circumstances. The node expresses these conditions through property declarations that should always hold.
